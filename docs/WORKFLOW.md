# 协作流程：Claude 策划审查，ChatGPT 开发

更新日期：2026-09-28。用户决定：**Claude 负责策划、设计和审查，并把具体开发任务拆成任务单；ChatGPT（Codex）按任务单写代码。** 用户负责拍板和在两者之间传递任务。

## 分工

| 角色 | 负责 | 不做 |
|---|---|---|
| 用户（院长本人） | 确认方向、选择方案、把任务单交给 ChatGPT、决定合并 | — |
| Claude | 玩法与系统设计（`GAMEPLAY.md` 等），知识库规划，拆任务单（`tasks/`），审查 ChatGPT 的提交 | 不承担主要编码；只在审查需要时写小修正或示例 |
| ChatGPT | 按任务单实现代码、测试、截图，更新 `HANDOFF.md` 和任务单的执行记录 | 不擅自改设计决定、不扩大任务范围 |

## 一个任务的流转

1. **Claude 写任务单**：`tasks/T###-简称.md`，写明目标、依据、范围（做 / 不做）、验收标准、交付方式。任务单状态为“待开发”。
2. **用户交给 ChatGPT**，可以直接这样说：
   > 阅读 AGENTS.md、docs/WORKFLOW.md 和 tasks/T001-iso-scene.md，按任务单完成开发。
3. **ChatGPT 开发**：
   - 从最新 `main` 建分支 `codex/T###-简称`；
   - 只做任务单范围内的事；
   - 运行任务单要求的检查，保存截图；
   - 在任务单末尾的“执行记录”里写：做了什么、运行了哪些命令和结果、没做到或没验证的部分、发现的设计问题；
   - 更新 `HANDOFF.md`，推送分支并开 PR 到 `main`（无法开 PR 时告诉用户分支名）。
4. **Claude 审查**：读 diff、运行检查、渲染或截图对比，把结论写进任务单的“审查记录”：**通过** / **需修改**（逐条列出）。需修改时回到第 3 步。
5. **用户合并**：审查通过后由用户合并（或明确授权 Claude 合并）。任务单状态改为“已完成”。

## 规则

- 设计以 `GAMEPLAY.md` 为准。ChatGPT 发现设计缺口或矛盾时，写在执行记录的“问题与建议”里，由 Claude 和用户决定，不自行改设计文档的决定。
- 任务单里没写的功能不做；做不完的部分如实标“未完成”，不宣称通过。
- 新代码在 `v2/` 目录重做（用户已同意重做）。旧原型（根目录 `index.html`、`src/`、`tests/`）保留不动，直到任务单明确要求替换或删除。
- 不引入第三方依赖和构建工具，除非任务单允许。
- 交付门槛沿用 `docs/QUALITY_GATE.md` 的三层要求：自动检查、在正常入口实际运行、玩家可理解性。旧原型专用的检查项（选址、开业等）只适用于旧代码。
