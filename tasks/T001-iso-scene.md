# T001 等轴场景基础

状态：待开发
依据：`GAMEPLAY.md` 第 8 节；效果图 `art/concepts/v03/c-isometric.png`；效果图源码 `art/concepts/v03/src/isometric.html`
分支：`codex/T001-iso-scene`

## 目标

在新目录 `v2/` 搭起游戏的等轴 2.5D 场景：能画出医院、能拖动缩放、能点选人物。这是之后所有玩法（患者流、建设、汇报）的画面基础。

完成后，打开 `http://localhost:4173/v2/`，在手机竖屏上看到的画面要达到效果图 C 的水平，并且可以交互。

## 背景

- 用户选定了美术方案 C（等轴 2.5D，外墙剖开可见室内）。效果图是用 Canvas 2D 代码画的，`isometric.html` 里的投影、体块、墙、人物、树、车辆等绘制函数**可以直接移植**，但要整理成可复用的模块。
- 游戏要重做（用户已同意），新代码放 `v2/`，旧原型保留不动。
- 之后会有“建设模式”（玩家划房间、摆设备）和“实时患者流”，所以场景**必须由数据驱动**：房间、墙、门、家具、人物都是数据，渲染器读数据来画，不能像效果图那样写死一长串绘制调用。

## 范围

### 要做

1. **目录与入口**
   - `v2/index.html`、`v2/style.css`、`v2/src/*.js`（原生 ES 模块，无第三方依赖、无构建步骤）。
   - 修改 `server.mjs` 的白名单，允许访问 `v2/` 下的文件。`/v2/` 返回 `v2/index.html`。不要改动旧入口的行为。
2. **等轴渲染模块**（建议 `v2/src/iso.js`）
   - 平面坐标 ↔ 屏幕坐标的投影和反投影（反投影用于点击拾取和以后的建设模式）。
   - 绘制原语：地板（带瓦片线）、体块（顶面、左面、右面三色 + 描边）、墙段（全高 / 半高剖切 / 低矮前墙，可带窗户、门洞）、人物（站、坐、背身、走动姿势；医生、护士、技师、患者的外观）、树、汽车、救护车。
   - 按设备像素比（devicePixelRatio）绘制，画面在高清手机屏上要清晰。
3. **场景数据**（建议 `v2/src/layout.js`，或 JSON）
   - 用数据描述效果图里的同一家医院：诊室、检验科、候诊大厅、放射科、病房 5 个房间，墙和门洞，全部家具设备，室外道路、停车场、救护车、树，以及效果图里的全部人物（带角色和姿势）。
   - 数据格式要为以后的建设模式考虑：房间有类型和范围，家具有类型、位置和朝向。在执行记录里简要说明格式。
4. **深度排序**：所有物体按正确的前后关系绘制。人物站在家具后面时要被遮挡，站在前面时要遮挡家具。长墙要分段排序，不能整面墙盖住房间里的东西。
5. **相机与交互**
   - 单指拖动平移，双指捏合缩放，电脑上鼠标拖动 + 滚轮缩放。
   - 缩放和平移有范围限制，不能把医院拖出屏幕外找不回来。
   - 默认视角与效果图一致。
6. **点选**
   - 点人物：人物脚下出现高亮圈和名牌，底部弹出一张**占位病历卡**，显示姓名、角色，以及“诊疗详情将在后续任务接入”这类说明。
   - 点空白处：关闭病历卡、取消选择。
   - 点选判定要准确，重叠时优先选前面的人物。
7. **界面外框**：顶栏（医院名、日期时间、资金、汇报按钮带未读数）和底部 6 个入口（医院、汇报、建设、人事、规则、资金），样式参照效果图 C。除“医院”外，其余入口点开只显示一个“即将开放”的占位面板。
8. **布局适配**：手机竖屏铺满；平板和电脑上居中显示竖屏画幅（与旧原型的做法一致）。
9. **测试**：`tests/v2/` 下用 `node --test` 写单元测试，至少覆盖投影与反投影互逆、深度排序键的前后关系、点选命中（给定屏幕点返回正确人物）。把 `v2/src` 的语法检查和这些测试加入 `npm run verify`。

### 不做

- 不做患者流、模拟、时间推进、存档、汇报内容、建设模式、知识库数据。
- 人物可以站着不动，或做简单的原地动画；不需要寻路和走动逻辑。
- 不改旧原型的 `index.html`、`src/`、`tests/` 里的已有测试。
- 不引入第三方库、框架、打包工具。

## 验收标准

1. `npm run verify` 通过（包含新增的 v2 测试），贴出命令和结果。
2. `npm start` 后打开 `/v2/`，在 390×844 竖屏、3 倍像素比下截图，保存到 `art/screens/T001/v2-default.png`。和 `art/concepts/v03/c-isometric.png` 相比：内容一致（5 个房间、家具、人物、室外），质量不低于效果图，没有明显的遮挡错误。
3. 再截两张图：拖动并放大到病房附近 `art/screens/T001/v2-zoom.png`；点选一个患者并弹出占位病历卡 `art/screens/T001/v2-selected.png`。
4. 浏览器控制台没有错误。
5. 在执行记录里说明：拖动、缩放、点选在真实浏览器里是否亲自操作验证过；在手机或模拟移动端上是否测过触控。没测的写“未验证”。
6. 旧入口 `/` 仍能正常打开（只需确认没有被改坏）。
